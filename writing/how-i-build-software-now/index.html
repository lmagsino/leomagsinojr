The shift

The bottleneck moved, so I moved

For most of my career, the unit of work was the keystroke. You thought, you typed, you tested, you shipped. AI pair tools chipped at that from 2022 onward, but the job stayed the same shape: an engineer with a very fast autocomplete.

Somewhere over the last year and a half, the shape changed. The agents got good enough to take a ticket from description to pull request on their own. Anthropic’s 2026 Agentic Coding Trends report describes the same thing I was living: being a software engineer increasingly means orchestrating agents that write code — evaluating their output, giving direction — rather than typing the code yourself. The industry phrase is agentic engineering. My phrase is simpler: I stopped being the typist and became the line manager.

But here’s the part that took me longest to accept: when agents write the code, writing code stops being the constraint. Deciding what to build, reviewing what was built, and verifying it actually works become the constraint. Any hour I spend has to go where the bottleneck now is.

That realisation produced the two systems I now run every working day: AI Light Factory on the build side, and Three-Pass Review on the review side. Both are open source. What follows is how they fit together into one working day.

The whole line

Here is the end-to-end shape. Solid boxes are me. Dashed boxes are agents. Every ◆ is a gate where I approve before anything moves on — and the last step, the merge, is one no agent can perform, enforced by hooks and shims rather than by a sentence in a prompt.

A working day

Mornings are for decisions. Agents get the afternoon.

In practice the line gives my day a rhythm. Decisions, plans and tickets happen while I’m sharpest. Then the dev loop runs unattended while I do the work only I can do — architecture conversations, mentoring, the odd production question. Late in the day I come back, read what needs me, and merge.

The build side

AI Light Factory: the agents draft, I merge

The name comes from Addy Osmani’s distinction in Software Factories, Light and Dark. A dark factory ships code no human has read. A light factory keeps a human in the loop, and gives a loop only as much autonomy as you can cheaply and reliably verify. I take the light side literally: my judgement moves to where it pays off, and everything in between runs unattended.

The factory is five stages, and I built it after a year of running agent lines on production codebases and watching exactly where they go wrong:

StageWhoWhat I decide
1 · Decide Architect agent, running Matt Pocock’s grill-with-docs, grills me one question at a time and writes the ADRs Do the decisions hold?
2–3 · Plan Planner writes the plan with Addy Osmani’s agent-skills, then publishes tickets with blocking edges via to-tickets Right plan? Right tickets?
4 · Dev loop Developer builds, a Reviewer from another vendor reviews, Guardian sweeps threads Nothing. It runs unattended
5 · Verify Verifier drives the running app in every feature-flag state Merge. Always mine

Three defaults in there came straight from pain:

A reviewer from the same vendor shares the builder’s blind spots

When the model that wrote the code also reviews it, its misses are silent — both passes share the same gaps. So in my setup Claude Code fills the Developer, Guardian and Verifier seats, and OpenAI’s Codex fills the Reviewer seat: Claude writes the code, Codex reads it. Different vendor, fresh context, by design. If you put the same vendor in both seats, every PR says so.

Unlimited parallelism is a trap

Run wide open, a fleet of agents burns a week of model budget in days and opens more PRs than any human can review. Two lanes is the ceiling, and it isn’t a starting point to tune upward.

Guardrails are code, not prompts

The line never marks a PR ready, never approves, never merges. That isn’t a sentence in a prompt a model might skip — it’s a guard hook and a pair of git/gh shims that refuse those commands for every worker, whatever agent sits in the seat.
